Bitneedle is the public reference code and format for reading and validating **picture-record objects** — visual, record-like images that carry recoverable audio data inside their pixels. A Bitneedle record is a single PNG that looks like a vinyl record and is the audio: the pixels along the visible groove decode back into the exact bytes of a canonical record stream.

The [Bitneedle repository](https://github.com/wavey-ai/bitneedle) is published so the objects can be inspected, verified, and played back with self-sufficient tools that do not depend on any single vendor.

## Who this is for

Bitneedle is aimed at people who need to work with picture-record objects directly rather than through a hosted platform:

- **Artists and artist entities** authoring their own Bitneedle records under the Wavey Artist Source Licence.
- **Collectors** who want to hold a record as a self-contained file and confirm it decodes to real audio.
- **Archivists** preserving releases in a format where the audio is carried by the object itself.
- **Marketplaces and players** integrating decode, verification, and playback without proprietary tooling.
- **Independent developers** building inspection, playback, or preservation software against the open format.

The reference code is not the commercial Bitneedle authoring platform. Record labels, platforms, and other commercial users need a separate licence — see [Licensing](#licensing).

## The format at a glance

A Bitneedle picture record is a 576 × 576 RGBA PNG. The visible groove carries audio; two metadata bands carry the descriptor that tells a decoder how to read everything else.

```text
576 × 576 PNG/RGBA
┌──────────────────────────────────────────────────────────┐
│ Outer metadata band  ── BRD1 begins here                 │
│  ┌────────────────────────────────────────────────────┐  │
│  │ Main visible groove                                │  │
│  │   direct RGB pixels → exact BRS1 bytes             │  │
│  │      ┌──────────────────────────────────────┐      │  │
│  │      │ Inner metadata band ── BRD1 continues│      │  │
│  │      │ Label / optional BSC1 carrier pixels │      │  │
│  │      └──────────────────────────────────────┘      │  │
│  └────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

### The format stack

| Layer | Magic | Purpose |
| --- | --- | --- |
| Raster | PNG | Exact 576 × 576, 8-bit RGBA carrier. |
| Descriptor | `BRD1` | Geometry, exact record-stream length, release metadata, optional signatures. |
| Record stream | `BRS1` | Compact binary payload metadata, CRC-protected chunks, tracks, and entries. |
| Sidecar | `BSC1` | Optional pair-sign auxiliary carrier for text, JSON, images, and opaque extras. |

At decode time the flow is deterministic:

```text
PNG bytes → exact RGBA
   ├── trace outer + inner spirals → BRD1 (profile, b_value, BRS1 length, metadata)
   └── trace main groove using b_value → RGB → BRS1 bytes → chunks → tracks and payload
```

Two record profiles are defined: `single45` (7-inch style) and `lp` (long-play style). Both encode audio as **direct RGB → bytes**; there is no groove patternisation or reverse map.

## Repository and crate layout

The reference implementation is a Rust workspace. Crates split cleanly between **decode / verify / interoperability** (open) and **record authoring** (source-available under the artist licence).

| Crate | Licence | Role |
| --- | --- | --- |
| `record-core` | Apache-2.0 | Shared geometry, record profile, chunk/gap, and spiral-index primitives. |
| `record-descriptor` | Apache-2.0 | BRD1 descriptor wire format, parsing, and decoding. |
| `record-decode` | Apache-2.0 | Decode and inspect Bitneedle picture-record images. |
| `record-verify` | Apache-2.0 | Canonical hashing, registration receipt chains, signature verification. |
| `record-sidecar` | Apache-2.0 | Sidecar (BSC1) structures for recovery and inspection. |
| `record-wasm` | Apache-2.0 | WebAssembly facade for decode, verify, and sidecar inspection. |
| `player-wasm` | Apache-2.0 | WebAssembly playback orchestration helpers (no record authoring). |
| `bytes2rgb` | Apache-2.0 | Low-level pixel-to-byte utilities used by decoder and verification tools. |
| `bitneedle-id` | CC0-1.0 | Typed prefixed ULID identifiers for public record objects. |
| `record-groove` | Artist Source | Byte-to-pixel carrier encoding, toned palette, and OKLCH helpers. |
| `record-label` | Artist Source | Canonical label geometry and spindle/dink cutout authoring primitives. |
| `record-render` | Artist Source | Constructs and renders the finished record PNG. |
| `record-cut` | Artist Source | Canonical BRS1 authoring, BRD1 authoring, and GAP1 authoring. |
| `record-cut-wasm` | Artist Source | WebAssembly facade for record authoring. |

## Licensing

Bitneedle uses a split licensing model. Each crate's `Cargo.toml` and `LICENSE` file are the source of truth.

- **Decode, verify, and interoperability crates** are released under the **Apache License, Version 2.0**. Anyone can read, verify, and play Bitneedle records under Apache-2.0 terms.
- **Record-authoring crates** — the ones that construct, encode, or render Bitneedle records — are released under the **Wavey Artist Source Licence**. That licence permits qualifying Artists and Artist Entities to create and sell their own Bitneedle records, but reserves commercial authoring, platform, and label use.

Any patent licence is limited to the express terms of the applicable component licence. Publication of the repository is not intended to dedicate patent-pending technology to the public or waive patent rights beyond those express terms.
